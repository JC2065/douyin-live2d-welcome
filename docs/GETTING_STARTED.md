# 安装、使用与排障

[返回 README](../README.md)

## 环境检查

在 PowerShell 运行 `py -3.12 --version` 和 `git --version`。需要 Python Launcher；Microsoft Store 的 Python 占位程序不足以安装。当前脚本面向 Windows，其他系统尚未验证。

## 安装过程

`setup.ps1 -AcceptLive2DTerms` 在项目内创建 `.venv`，安装锁定依赖，下载指定提交的模型仓库，复制 Haru 示例，移除示例动作附带的声音，再下载 PixiJS、渲染插件和 Live2D Core。它不连接抖音，不设置开机自启。

渲染库版本和模型提交已指定；Core 与模型条款仍使用上游当前地址，尚无完整资产哈希锁定。已有 `vendor/pixi-live2d-display` 时，脚本不会重新校验或切换其提交。

## 日常操作

双击 `start.cmd`，在角色页启用声音后模拟进房。相同 ID 用于验证冷却，同名不同 ID 分别欢迎。

欢迎词配置位于 `welcome_presets.json`，内置 12 条技术直播短句。每轮打乱后依次使用全部预设，轮次交界也不连续重复。每句使用 `{name}` 插入昵称，修改后重启服务生效。语音和气泡共用一次选出的文本。默认音色位于 `app.py` 的 `worker()`，为 `zh-CN-XiaoxiaoNeural`；当前没有设置保存界面。

暂停会停止当前播放并使待播欢迎失效；恢复不会补播暂停期间的事件。

## 独立窗口与采集

1. 点击「打开独立角色窗口」，必要时允许浏览器弹窗。
2. 新窗口再次启用声音；旧窗口播放权可能最多约 30 秒后释放。
3. 在直播软件尝试窗口采集与绿幕色键；如支持网页源，可尝试透明页面。
4. 先录制短片验证角色、气泡和声音，排查重复收音，再决定用于直播。

这不是对所有直播伴侣版本的支持保证。程序不会检测主播讲话，需要时手动暂停欢迎。

## 停止与重启

关闭浏览器不会停止后台服务。需要前台运行时，在端口未占用的情况下执行：

```powershell
.\.venv\Scripts\python.exe app.py
```

在该终端按 `Ctrl+C` 停止。后台进程可在任务管理器根据 `app.py` 命令行及项目路径识别后结束；不要结束其他项目的 Python。`data/server.pid` 仅作参考，不要盲目按旧 PID 杀进程。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 找不到 `py` 或 Python 3.12 | 安装 Python 3.12 与 Launcher，重新打开终端 |
| 依赖或素材下载失败 | 查看最后一条错误，检查对应上游网络，修复后重新运行安装脚本 |
| 页面打不开 | 检查 `data/server.err.log` 和 18765 端口占用 |
| 角色不出现 | 查看角色顶部错误；确认素材目录存在且浏览器支持 WebGL |
| 提示声音未启用 | 点击角色上的按钮，等待窗口就绪 |
| 另一个窗口正在播放 | 关闭其他角色页，等待最多约 30 秒；自动测试也会争用播放权 |
| 已排队但没有声音 | 检查角色错误、系统音量、浏览器静音与 TTS 网络；语音回退也可能失败 |
| 同一个人没有再欢迎 | 满 60 秒后需要新的进房事件，不会定时自动补播 |
| 录像没有声音 | 检查直播软件音频源，浏览器发声不代表已采集 |
| 连接失败 | 查看连接面板错误；确认可选连接器已安装、网络可用且正在开播 |
| 已连接但不欢迎 | 区分消息数与进房数；启用角色声音，再由另一个账号进房验证。不是所有观众都一定有进房推送 |

## 更新

停止服务，保存自己的修改，再执行 `git pull --ff-only`。涉及依赖或素材更新时，阅读条款后重新运行安装脚本。

## 记住直播间

连接成功后点击「记住当前直播间」，本机 `data/room-binding.json` 保存稳定的网页直播间号。服务下次启动自动连接，不需要再粘贴临时分享链接；未开播或网络异常时会按连接策略重试。

「断开连接」只停止本次连接，不删除绑定；「取消绑定」停止下次自动连接，不中断当前连接。若主播更换直播间号，重新连接并绑定即可。页面刷新或浏览器限制时，声音仍可能要点击「启用欢迎声音」。绑定文件不会上传到 GitHub。

## 互动朗读与声音恢复

控制台三个开关分别控制点赞、礼物、评论，修改后自动保存到 `data/interaction-settings.json`。暂停欢迎会暂停所有类别，并使待播事件失效。连续新人会合并成最多三人一组；同一用户 60 秒内的重复进房仍忽略。

若显示「点此恢复欢迎声音」，点击后继续待播内容。每次播放会尝试恢复 AudioContext；浏览器或系统静音仍需手动检查。失败提示会保留到成功播放，不再被每次轮询清掉。

诊断区区分平台收到的推送、接受的事件、真正回报完成的播放。后者仍不能证明直播软件已录入声音。评论、礼物和点赞的真实推送数量受平台接口影响，不能保证每个行为都有消息。

多窗口时，点击正在查看的角色页的声音按钮即可接管；关闭或刷新页面会主动释放。控制台「测试声音」会排入一条明确标为声音测试的欢迎，便于不等真人进房也能排查。

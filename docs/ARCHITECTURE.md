## 本地接口

无版本稳定承诺或用户认证，仅供本地开发。请求体为 JSON。

| 接口 | 说明 |
| --- | --- |
| `GET /api/status` | 模式、冷却、暂停、序号、播放器、日志、队列长度 |
| `POST /api/enter` | `{"uid":"demo-001","name":"小明"}`；返回 `accepted` 和文本或原因 |
| `POST /api/mute` | 切换暂停，不是幂等的设置接口 |
| `GET /api/events?after=0&client=...` | 获取增量事件并续约播放权；会影响状态，不适合作为监控接口 |

`accepted: true` 表示进入欢迎流程，不是音频完成的确认。

## 时序与容量

- 排队超过 120 秒的任务过期并计入统计。连续进房按 0.8 秒、最多三人一组生成欢迎。
- 冷却在生成语音前记录；失败或未消费不会撤销冷却。
- 服务端待处理队列最多 120 条、事件环 120 条、日志环 80 条。
- 前端每次仅接收一条未确认事件，`finished` 确认后才发送下一条。普通失败重试一次，40 秒无完成回报也会重试；最多保留 120 秒，过期和失败都有统计。确认丢失时可能重播，不保证恰好一次。
- 单个活动窗口持有约 30 秒租约，断开后其他窗口可接管。
- TTS 超时后尝试浏览器语音，不保证离线可用。暂停使旧代次事件失效。

CI 验证冷却、分享链接、多人分组、播放确认/重试、互动内容与优先级等规则。UI 测试会占用播放权并切换暂停，须在没有正在使用的角色页时运行。已有一次完整本地流程通过；同时打开用户角色窗口时，复测曾因播放权竞争而气泡等待超时。

抖音 WebSocket 与直播统计消息已实测；已有一次真实进房触发与浏览器播放回报通过；直播伴侣采集、长期高负载和干净系统安装尚未验证。增加证据后再更新项目状态。

## 连接管理

- `POST /api/connection/start`：`{"room":"分享链接或数字直播间号"}`，异步解析并连接，已有连接时拒绝重复启动。
- `POST /api/connection/stop`：断开连接，不关闭角色或本地服务。
- `/api/status` 中 `connection` 提供状态、房间号、消息/进房/接受/跳过计数与错误；只统计收到的进房消息，不等于平台全部进房人数。
- 状态包括解析、连接、已连接、重连、停止、结束与失败。窗口没有启用声音时，进房会计入跳过，不补播。
- 服务返回 `server_id`，角色页发现服务重启后重新同步事件序号，避免旧序号遮蔽新欢迎。

`POST /api/playback` 接收当前播放窗口对事件的 started/finished/failed 回报，`/api/status` 提供最近回报。数字 ID 字段兼容和无效 ID 过滤有回归测试。

## 互动队列

`interactions.py` 格式化评论/礼物/点赞，去重消息 ID 与礼物连击结束事件。同一用户点赞 8 秒内去重。生成队列 `SpeechQueue` 与未开始的待播事件都按礼物、评论、欢迎、点赞优先排序；已经开始的语音不抢占。

`POST /api/interactions` 接收 `{"like":true,"gift":true,"chat":true}`，将设置保存到本地 data。`/api/status` 返回 interactions 和按类别的收到/接受/已播计数。

`GET /api/events` 增加 `ready`（声音是否可用）；租约延长到 30 秒。`POST /api/playback` 增加 attempt、detail 和 blocked 阶段；权限阻止不消费失败重试次数。`after` 参数为兼容旧调用保留，新版按未确认事件调度。

连接已建立但 90 秒没有收到消息时，后台会关闭旧连接并进入重连。

`npm run test:audio` 使用独立 Edge 页面、模拟 API 和内存 WAV，验证被阻止时保留恢复按钮，以及三组七人完成且没有重复回报。它不向真实直播间提交模拟互动，也不证明观众端收音。需要本地服务和模型素材已就绪，但测试音频无需 TTS 网络。

用户点击声音按钮时通过 `POST /api/player/claim` 接管播放权，旧窗口后续轮询被拒绝并停止播放。页面退出时通过 `POST /api/player/release` 释放自己的租约；旧窗口不能释放新窗口租约。

# 抖音接入：实验状态

[返回 README](../README.md)

`douyin_bridge.py` 只处理上游进房消息中明确的进入事件，将 ID 和昵称发送至本地服务。它不发送弹幕、不自动开播、不运行上游 AI 回复或冷场播报。

**已使用真实直播间验证 WebSocket 连接和统计消息；已完成一次真实进房触发与浏览器播放完成回报验证；事件不保证覆盖所有观众，直播伴侣收音尚未验证。**

## 前置条件

- 本地服务运行且角色声音已启用；直播间正在直播。
- Node.js 在 PATH 中。
- 自行评估 [上游连接器](https://github.com/Primusse/douyin-ai-assist) 的许可和适用条件。检查的提交未发现许可文件，因此本仓库不分发、不自动安装它。
- 桥接按提交 `417e21474f278222a0d809ff9b15a8068e80b31b` 编写，预期目录 `vendor/douyin-ai-assist`。

原部署对上游 `live_client.py` 做了两处本地修改：`requests.get(...)` 增加 `timeout=15`；`run_forever` 的 `cert_reqs` 从 `ssl.CERT_NONE` 改为 `ssl.CERT_REQUIRED`。这些修改没有随第三方源码发布。上游历史固定签名参数仍需真实开播验证或升级。

## 手动启动

依赖准备好后，将示例数字替换为自己的直播间号：

```powershell
.\.venv\Scripts\python.exe connect_douyin.py 123456789
```

命令行只提交连接请求，随后退出。也可直接在控制台粘贴整段分享文字并点击「连接直播间」，用「断开连接」停止。控制台显示连接状态、进房数和接受/跳过计数。分享跳转只允许官方直播相关域名，带追踪参数的原始链接不会写入状态记录。

连接断开时按 2、4、8 秒逐步重试，上限 30 秒；手动断开或收到结束事件后停止。该重试策略尚未做长时间真实断线验证。反馈请提供脱敏错误，不要公开 Cookie、凭据或观众名单。

## ID 字段兼容

实测发现连接器将 User 的字段 1 声明为 string，而进房数据使用 uint64；昵称可用时 ID 仍可能为空。项目在该字段类型不匹配时读取保留的 Protobuf 数字字段，再回退至其他稳定 ID，避免用昵称去重。同名观众不会因此共享冷却；确实缺少稳定 ID 的消息仍跳过。

控制台日志区分真实进房、语音准备、开始播放和浏览器播放完成。播放回报能验证网页流程，不能替代直播音轨或观众端收听验证。
